# Case 4, 6, 7, 8, 9: 사내 업무 자동화, 규정 색인·판정, RAG·분류기, 전략 대안 비교 및 복합형 스킬

## 1. 언제 이 스킬을 쓰는가
- **Case 4 적용 상황:** 비효율적인 수작업 업무(엑셀 수작업, 반복 대사, 양식 변환 등)를 자동화하는 운영 도구 개발 과제. 자동 처리 영역과 사람의 판단이 필요한 '수동 검토 큐'의 분리가 핵심.
- **Case 6 적용 상황:** 수십~수백 페이지의 사내 규정집, 정책 매뉴얼, 지침서, 개정 전후 비교표를 기반으로 규정 위반 여부나 적격성을 판정하고 근거 조항이 명시된 검토 보고서를 작성하는 과제.
- **Case 7 적용 상황:** 문서 기반 질의응답 챗봇(RAG), 사내 문서 자동 분류기 구축 과제. 외부 API가 금지된 환경에서 환각(Hallucination) 통제 및 근거 인용이 핵심.
- **Case 8 적용 상황:** 기술 도입, 아키텍처 선정, 정책 변경 등 복수의 대안을 비교 분석하여 경영진/의사결정권자에게 최적 권고안과 포기 사유, 실패 조건(리스크)을 보고하는 과제.
- **Case 9 적용 상황:** 소과제가 2개 이상이거나, 데이터 분석 결과가 후속 웹 대시보드/API 개발로 이어지는 파이프라인 결합 과제.

### ⚙️ Case 4. 사내 업무 자동화 / 운영 도구 구현 미션 (출제 확률: 중상)
* **연동 스킬:** `.probe-kit/skills/case4_policy_rag_doc.md`
* **판별:** *"~수작업 업무가 비효율적이다"*라는 서술 + 엑셀·양식·로그 파일 제공.
* **전용 필수 질문:**
  * *"현재 이 수작업 업무는 몇 단계로 진행되며, 단계마다 사용하는 파일/양식이 무엇인가요?"*
  * *"사람이 수작업할 때 실수가 가장 자주 나는 단계는 어디이며, 시스템이 100% 자동 확정할 영역과 '수동 검토(보류)'로 분류해 사람에게 넘겨야 할 경계 기준은 무엇인가요?"* (현업 회계팀 관점: 자동화할 일과 사람 판단이 필요한 일의 구분)
* **무감점 Solve 시퀀스:**
  1. 현행 업무 단계 목록화 → 가장 병목/실수가 심한 핵심 단계 특정 → 입출력 양식 확정.
  2. 전체를 무리하게 자동화하려 하지 말고, 애매한 케이스는 `수동 검토 필요(사유 포함)`로 플래그를 찍어 분리 출력하도록 서브에 위임.
  3. 깨진 입력(빈 행, 형식 오류)을 넣어 죽지 않고 예외 리포트로 빠지는지 검증.

### 📄 Case 6. 방대한 규정/정책/매뉴얼 기반 의사결정 & 문서 산출물 미션 (출제 확률: 중상 — 결합 출제 유력)
* **연동 스킬:** `.probe-kit/skills/case4_policy_rag_doc.md`
* **판별:** 여러 개의 긴 사내 규정집, 정산 기준서, 개정 전후 비교표 제공 + 판별 로직 또는 기획서/검토 보고서 제출.
* **전용 필수 지시 & 질문:**
  * *(서브 에이전트 지시)* *"문서를 통째로 요약하지 마. 계산 기준, 예외 조항('단, ~는 제외'), 개정 일자가 등장하는 정확한 문서명과 조항(라인 번호) 위치를 먼저 모두 찾아서 표로 색인화해 줘."*
  * *(실무자 DM)* *"A 일반 규정과 B 예외 조항(또는 구본과 개정본)이 `[특정 케이스]`에서 충돌하는데, 실무에서는 어느 기준을 우선 적용하나요?"*
  * *(실무자 DM)* *"이 최종 보고서/결과물을 누가 읽으며, 읽고 나서 어떤 의사결정을 내리나요?"*
* **무감점 Solve 시퀀스:**
  1. 서브(`Luna 6 xhigh`)로 원문 근거 위치 색인표 확보 → 상충 조항 실무자 확인 → 경계값(이상/초과/미만) 조건문 구현.
  2. 결과물이나 보고서에 단순 결론(O/X)만 적지 말고, **'어느 문서 몇 번 조항에 근거하여 판단했는지'** 출처를 함께 출력/명시. 근거가 없는 항목은 추측하지 말고 `'확인 필요'`로 분리 표기(현업 분석가 관점: 근거와 추측 구분).

  * *"AI가 틀린 답(환각)을 내놓으면 현업에서 어떤 문제가 생기며, 사람이 최종 확인하는 단계가 있나요?"*
* **무감점 Solve 시퀀스:**
  1. 외부 API 키 사용은 금지되므로 반드시 환경 내에 제공된 로컬/내장 모델이나 규칙+프롬프트 파이프라인만 사용.

## 4. 업무 자동화·수동 검토 분리 규칙 (Case 4)

현업 업무(회계, 법무, 품질 승인 등) 자동화의 핵심은 100% 완벽한 자동화가 아니라, **"위험한 건을 안전하게 사람에게 넘기는 안전장치"**에 있다.

### 처리 분류 3대 영역
1. **`AUTO_APPROVED` (자동 확정 승인):**
   - 모든 필수 서류 구비, 금액 및 규정 한도 100% 충족, 블랙리스트 미포함.
2. **`AUTO_REJECTED` (자동 확정 반려):**
   - 위조 서류, 기한 초과, 명백한 규정 위반(예: 지원 불가 품목).
3. **`MANUAL_REVIEW` (수동 검토 보류):**
   - 금액이 승인 한도 경계선(±5% 이내)에 위치한 경우.
   - 규정에 명시되지 않은 신규 카테고리 항목.
   - 첨부 영수증의 글자가 뭉개져 OCR 신뢰도가 80% 미만인 경우.
   - 분리 사유(`review_reason`)와 원본 식별자를 명시하여 검토자 전용 큐 파일(`manual_review_queue.csv`)에 기록.

### 파이프라인 출력 예시 포맷
```json
{
  "transaction_id": "TX-20261028-0912",
  "decision": "MANUAL_REVIEW",
  "review_reason": "신청 금액(1,050,000원)이 기본 승인 한도(1,000,000원)를 5% 초과하여 부서장 추가 결재 승인 필요",
  "evidence": "규정집 제4조 2항 (한도 초과 예외 품의 조항)",
  "processed_at": "2026-10-28T14:30:00+09:00"
}
```

## 5. 방대한 규정 조항·라인 번호 색인화 및 충돌 처리 규칙 (Case 6)

### `grep -n` 활용 조항 색인화 절차
문서 전체를 프롬프트에 넣으면 컨텍스트 폭발 및 환각이 발생하므로, 터미널에서 핵심 키워드의 라인 번호를 먼저 색인한다.

```bash
# 1. 계산 기준, 한도, 예외 조항 라인 검색
grep -n -E "제[0-9]+조|한도|제외|단,|경우|지급|불가" docs/company_policy.md

# 2. 개정 일자 및 부칙 검색
grep -n -E "시행일|개정|부칙|효력" docs/company_policy.md
```

### 조항 -> 라인 색인표 표준 양식
| 문서명 | 조항 번호 | 라인 번호 | 핵심 요건 및 적용 대상 | 예외 조건 ('단, ~는 제외') | 실무 적용 우선순위 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `policy_v2.md` | 제3조 (지원 한도) | L45-L52 | 1인당 연간 복지 포인트 120만원 지급 | 입사 3개월 미만 수습 사원은 월할 계산 | 일반 기본 원칙 |
| `policy_v2.md` | 제3조의2 (특별 지원) | L68-L75 | 반도체 공정 교대 근무자 대상 연간 50만원 추가 지급 | 재택 근무 부서 발령 시 즉시 지급 중단 | 제3조에 우선 적용 |
| `policy_v2.md` | 부칙 제2조 (경과 조치) | L210-L215 | 2026년 3월 이전 입사자는 구 규정 한도(100만원) 유지 | 신규 승진자는 신 규정 적용 | 경과 기간 한시 적용 |

### 충돌 조항 처리 프로토콜
1. **일반법 vs 특별법 원칙:** 일반 조항과 특정 대상(교대근무자, 특정 직무)을 지정한 예외 조항이 충돌할 경우 특별 예외 조항을 우선 적용한다.
2. **신법 우선 원칙:** 구 규정과 신 규정 개정본이 충돌할 경우 개정 부칙의 시행일을 확인하고 신 규정을 적용한다.
3. **해석 모호성 해결:** 두 조항의 해석이 정면 충돌할 경우 임의로 판단하지 않고 실무자 DM으로 질의하여 확정 답변을 받은 후 근거에 기재한다.

## 7. 전략 대안 비교표 작성 규칙 (Case 8)

전략 판단 및 의사결정 과제에서는 장단점만 나열하고 끝내는 미완성 답변을 절대 제출하지 않는다. 반드시 **최소 3개 대안**을 비교하고, **최종 권고안, 탈락 대안 사유, 실패 조건(리스크)**을 모두 포함해야 한다.

### 3대 대안 비교표 표준 양식
| 평가 지표 (가중치) | 대안 A: 온프레미스 경량 오픈소스 모델 (vLLM) | 대안 B: 완전 사내 규칙 기반(Rule-based) 엔진 | 대안 C: 상용 폐쇄망 어플라이언스 도입 |
| :--- | :--- | :--- | :--- |
| **도입 및 구축 속도 (25%)** | 4점 (사내 인프라 즉시 배포 가능, 2주) | 5점 (스크립트 즉시 작성 가능, 3일) | 2점 (계약 및 납품 2개월 소요) |
| **정확도 및 환각 통제 (30%)** | 4점 (프롬프트+문맥 인용으로 95% 방어) | 5점 (규칙 100% 일치, 환각 0%) | 4.5점 (벤더 보증 모델 적용) |
| **초기 및 운영 비용 (20%)** | 5점 (기존 GPU 노드 재활용, 라이선스 무료) | 5점 (추가 인프라 비용 제로) | 1점 (라이선스 및 장비 수억 원 소요) |
| **비정형 문서 대응력 (25%)** | 4.5점 (자연어 질의 및 요약 탁월) | 1.5점 (양식 변경 시 정규식 재작성 필요) | 4.5점 (우수한 자연어 이해) |
| **종합 점수 (100점 만점)** | **87.5점 (최우수 권고안)** | 69.5점 (탈락) | 59.0점 (탈락) |

### 의사결정 3대 필수 서술 항목
1. **최종 선택 권고안:**
   - **대안 A (온프레미스 경량 오픈소스 vLLM 파이프라인)**을 최종 권고함. 기존 보유 인프라를 활용하여 추가 비용 없이 2주 내 실전 배포가 가능하며, 비정형 규정집 해석과 정확도 95% 이상을 달성할 수 있음.
2. **포기한 대안과 버린 구체적 이유:**
   - **대안 B 포기 사유:** 초기 구축 비용은 0원이지만 반도체 품질 규정집의 비정형 문맥과 잦은 개정 사항을 정규표현식/규칙으로 유지보수하는 데 막대한 엔지니어링 리소스가 영구적으로 소모됨.
   - **대안 C 포기 사유:** 상용 패키지는 신뢰도가 높으나 도입 기간이 2개월 이상 소요되어 금번 긴급 개선 일정(1개월 내 오픈)을 맞출 수 없으며 라이선스 비용 대비 ROI가 낮음.
3. **이 권고안이 실패할 수 있는 전제 조건(리스크)과 플랜 B:**
   - **실패 조건:** 향후 동시 접속자 수가 500명을 초과하여 로컬 GPU VRAM 병목 및 응답 지연(3초 이상)이 발생하는 경우.
   - **플랜 B:** 고빈도 질의 80%를 규칙 기반 캐시 레이어(대안 B의 경량형)로 우선 응답하고, 복잡 질의만 LLM으로 라우팅하는 하이브리드 아키텍처로 즉시 전환.

## 10. 보고서 및 후속 Q&A 작성용 [결정]-[근거]-[검증]-[한계] 예시

- **[결정]:** 사내 규정 질의 및 지원금 판정 자동화 시스템에서 모든 케이스를 100% 자동 판정하지 않고, 명확한 기준 충족 건만 자동 승인하되 경계값 및 규정 미명시 건은 `MANUAL_REVIEW` 플래그를 부여하여 담당자 검토 큐로 격리하고, 자료 부재 시 "자료에서 확인할 수 없습니다"로 엄격 제한하는 환각 차단 아키텍처를 결정함.
- **[근거]:** 실무자 DM 질의를 통해 잘못된 규정 해석으로 인한 오지급 발생 시 회수 절차가 극히 어렵다는 현업 리스크를 확인하였으며, AI의 그럴듯한 환각(Hallucination)보다 보수적인 수동 검토 분류가 비즈니스 관점에서 손실 비용을 원천 차단하는 최선책이라는 점을 근거로 삼음.
- **[검증]:** 규정 원문의 조항 및 라인 번호를 색인화한 후, 6개 유형의 자작 검증 세트(정상 2건, 경계 2건, 자료 부재 1건, 규정 충돌 1건)를 구축하여 파이프라인 테스트를 실행한 결과 6건 모두 기대 결과와 100% 일치함을 확인하였고, 미기재 항목에 대해 정확히 근거 부재 메시지가 반환됨을 검증함.
- **[한계]:** 키워드 및 규칙 기반의 색인 및 엄격한 근거 매칭 방식은 환각 발생률을 0%로 억제할 수 있으나, 규정 문서에 쓰인 단어와 신청자가 입력한 동의어(예: '식대' vs '중식비')가 완벽히 일치하지 않을 경우 정상 건임에도 수동 검토로 과다 분류될 수 있으므로, 향후 도메인 특화 동의어 사전(Thesaurus) 및 의미 기반 임베딩 검색의 보완이 필요함.
