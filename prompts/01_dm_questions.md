# 우측 DM '업무 담당자(실무자 에이전트)' 공략 매뉴얼

이 문서는 시험장 에디터 우측 DM 창에서 '업무 담당자(실무자 에이전트)'와 소통할 때 즉시 복사하여 질문할 수 있는 치트시트입니다.

---

## 1. 평가 에이전트 채점 요소 및 DM 대화의 중요성

20여 개의 평가 에이전트가 다음 항목들의 일관성을 교차 채점합니다:
1. **실무자 DM 대화 로그**
2. **메인/서브 Codex 프롬프트 및 토큰/비용 효율**
3. **도구 설정(`AGENTS.md`/하네스)**
4. **터미널/브라우저 검증 실행 기록**
5. **Git 로그·diff**
6. **제출 문서**
7. **후속 서술형 답변**

과제 지시서(`README.md`)는 의도적으로 모호하게 주어집니다. 초반 35분 동안 코딩을 서두르지 말고 아래 순서로 질문하여 숨은 조건(Edge Case)을 모두 캐내야 의도(Intent) 축 고득점을 받습니다. 한 번에 다 묻지 말고 대화 흐름에 따라 하나씩 질문하세요.

## 2. 절대 금지 사항 & 막혔을 때의 비상 질문

### ❌ 절대 금지 (감점 및 답변 거부)
- *"제가 당장 해야 할 일을 1, 2, 3번 순서로 정리해 주세요."*
- *"어떻게 구현하면 될까요?"*
> **주의:** 할 일 정리와 아키텍처 판단은 본인이 직접 수행해야 하며, 실무자 에이전트에게는 현업 맥락, 데이터 스펙, 업무 규칙, 예외 조건만 캐내야 합니다.

### 💡 막혔을 때의 비상 질문 (설계자 공인 힌트 유도)
과제 파악이 막혔거나 질문 방향을 잡기 어려울 때 아래 원문을 그대로 복사하여 질문합니다:

```text
과제 맥락을 정확히 파악하고 싶습니다. 현업 관점에서 제가 무엇을 먼저 물어봐야 할까요? 어떤 영역이나 조건에 대해 확인하면 좋을지 힌트를 주실 수 있나요?
```

### 💡 추가 상황별 비상 힌트 유도 질문
- **방향 상실/우선순위 혼선 시:**
```text
현재 과제 목표를 달성하기 위해 가장 핵심이 되는 도메인 규칙이나 가장 빈번하게 발생하는 실무 시나리오가 무엇인지 조언을 부탁드립니다.
```
- **조건 상충/데이터 모순 발견 시:**
```text
제공된 데이터/문서에서 상충되는 조건이 발견되었습니다. 실무에서는 이 경우 어느 조건이나 데이터 소스를 우선하여 처리하시나요?
```
- **시간 부족/범위 조정 필요 시:**
```text
제한된 시간 내에 최상의 품질을 내기 위해 우선순위를 조정하고자 합니다. 반드시 포함되어야 할 1순위 핵심 산출물과 후순위로 미뤄도 되는 항목을 구분해 주실 수 있나요?
```

## 3. DM 답변 기록 방법

> **`NOTES_TEMP.md` 실시간 기록 원칙:**  
> 실무자 DM 답변을 받는 즉시 `NOTES_TEMP.md`의 `## 1. 실무자 DM 확인 사항` 섹션에 `[질문 항목] - [실무자 확인 조건/수치/예외 규칙]` 형태로 한 줄씩 누적 기록하여 의사결정의 공식 근거로 보존합니다.

기록 형식 예시:
- `[취소 건 처리] - 취소·반려 상태의 주문 데이터는 총 매출 집계 및 전환율 계산 분모에서 완전 제외`
- `[중복 처리] - 동일 사용자 ID 및 주문번호의 중복 데이터는 최신 타임스탬프 기준으로 단일 건 유지`
- `[인터페이스 유지] - 기존 REST API 엔드포인트 경로(/api/v1/orders)와 응답 JSON 필드명은 변경 불가`

## 4. 실무자 DM 5단계 만능 12문 (전문)

### Step 1. 배경·타겟 유저 파악 (① 사용자·맥락 - 설계 전 필수)

#### Q1. 사용자 및 기존 업무 방식 파악
```text
안녕하세요 담당자님, 착수 전 현업 맥락을 파악하고 싶습니다. 이 결과물을 실제로 사용하는 주 타겟 사용자는 누구이며, 지금은 이 일을 어떤 방식으로 처리하고 있나요?
```

#### Q2. 기존 업무의 핵심 문제점(Pain Point) 발굴
```text
기존 업무 방식에서 가장 불편해하던 핵심 문제(Pain Point)나 실수가 자주 나는 지점이 어디인가요?
```

---

### Step 2. 입력 데이터 및 예외 발굴 (② 입력 데이터 - 구현 전 필수)

#### Q3. 데이터 형태 및 컬럼 도메인 의미 확인
```text
입력 데이터/자료는 어떤 형태이며, 각 항목(컬럼)이 현업에서 정확히 무엇을 뜻하나요?
```

#### Q4. 데이터 규모 및 결측치/오류 데이터 여부 확인
```text
데이터 양은 어느 정도이며, 실제 환경에서 형식이 깨진 경우(결측치, 중복, 오타, 타임존/단위 불일치 등)도 존재하나요?
```

---

### Step 3. 숨은 조건 캐내기 (③ 예외 처리 - 변별력 핵심)

#### Q5. 예외 상황(Edge Case) 처리 규칙 확인
```text
취소·반려 건, 중복 제출, 누락, 비정상 입력이나 권한 없는 접근 같은 예외 상황(Edge Case)은 어떤 기준으로 처리해야 하나요? (예: 중복 시 최신/최초 기준, 비율 계산 시 분모에서 취소 건 제외 여부 등)
```

#### Q6. 미인지된 단서 조항 및 현업 특수 규칙 발굴
```text
제가 아직 안 물어본 것 중에, 현업에서 이 업무를 처리할 때 꼭 알아야 할 예외 규칙이나 단서 조항이 또 있나요?
```

---

### Step 4. 출력·판단·제약 조건 확정

#### ④ 출력·완료 기준 (DoD)

#### Q7. 최종 결과물 형식 및 필수 포맷 기준
```text
최종 결과물은 어떤 형태여야 하며, 반드시 포함되어야 할 필수 항목이나 정렬·반올림·단위 기준이 있나요?
```

#### Q8. 완료 정의(DoD) 및 필수/선택 범위 구분
```text
현업 입장에서 어느 정도까지 구현되면 '성공적으로 완료(DoD)'되었다고 보시나요? 필수 구현 사항과 시간이 남을 때 추가할 사항을 나누어 주실 수 있나요?
```

#### ⑤ 애매한 판단 기준

#### Q9. 경계 영역 판단 및 기본값(Default) 규칙
```text
판단 기준이 애매한 경계 영역(예: 정상/이상 경계, 수동 검토 넘김 기준)은 보통 어떻게 판단하며, 기본값(Default)으로 무엇을 쓰면 되나요?
```

#### Q10. 다중 기준 충돌 시 우선순위 확인
```text
이번 과제에서 여러 기준이 충돌할 때 무엇을 가장 우선시하나요? (예: 데이터 정합성 vs 처리 속도, 기능 수 vs UI 직관성/안정성)
```

#### ⑥ 시스템·보안 제약

#### Q11. 시스템 불변 제약 사항 확인
```text
절대 변경하면 안 되는 기존 시스템의 제약 사항(API 인터페이스, 인증 방식, 라우터, DB 스키마, 파일 구조 등)이 있나요?
```

#### Q12. 보안 및 개인정보 노출 제한 확인
```text
개인정보나 사내 기밀 수치 등 민감한 정보 중에 결과물이나 로그에 그대로 노출하면 안 되는 항목이 있나요?
```

---

### Step 5. 가설 제시 및 최종 확정 (가산점 핵심)

#### 확정 질문. 요구사항 구조화 확인 및 구현 동의 구하기
```text
말씀해주신 내용을 바탕으로 요구사항을 [A, B, C]로 구조화하여, [X 기준]으로 예외를 처리하고 [Y 구조]로 우선 구현하려 합니다. 현업의 의도와 부합할까요?
```

## 5. 출제 예상 9대 케이스별 실무자 DM 전용 질문

### 📦 Case 1. 데이터 파이프라인 정제·집계 및 리포팅 미션

#### 집계 단위(Row 정의) 확인
```text
이 표에서 한 행(Row)은 무엇을 한 건으로 세나요?
```

#### 취소·중복 처리 및 타임스탬프 기준
```text
취소·철회된 건이나 중복 유입된 건은 집계(및 비율 계산 시 분모)에서 어떻게 처리하나요? 중복 시 최신과 최초 중 무엇을 기준으로 삼나요?
```

#### 기간 필터링, 타임존, 결측치 처리 기준
```text
기간 필터링 기준은 신청일인가요, 처리 완료일인가요? 타임존이나 단위 불일치, 결측치(null, -999) 처리 기준은 무엇인가요?
```

#### 최종 리포트 그룹화 및 출력 포맷 기준
```text
최종 결과는 어떤 단위(부서별/월별 등)로 묶으며, 컬럼명·정렬 순서·소수점 반올림 기준은 무엇인가요?
```


#### 대시보드/목록 최우선 노출 도메인 정보
```text
목록이나 대시보드를 보여줄 때 현업 사용자가 가장 먼저 확인해야 하는 핵심 정보(도메인 디테일)가 무엇인가요?
```

```text
이 지표가 이상(비정상)이라는 것은 수치로 어느 수준인가요? 정상/주의/위험을 나누는 명확한 임계값(Threshold) 기준이 정해져 있나요?
```

#### 모호한 전문 도메인 용어 확인
